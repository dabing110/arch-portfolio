## 五条核心判断（摘要）

1. **接入网关必须双栈**，不为「统一」硬塞一个组件。JT/T 808 是私有二进制 TCP 协议，EMQX 不支持也不该让它支持；MQTT 通道用成熟件。**统一发生在协议适配层，不在接入层**。
2. **弱网补传是生死线，不是附加功能**。移动性断连是常态，断点续传 + 五级优先级 + 防补传风暴决定完整性 SLO。
3. **时序库的决定性因素是设备基数，不是跑分**。50 万车 × 数百信号，InfluxDB 的 tag 高基数会 OOM；TDengine 的「一个设备一张表」天然匹配。这是结构差异，调优弥补不了。
4. **控车按安全分级，L3（行驶相关）在架构上不留通路** —— 不是权限没给，是协议解析层不存在那条指令码。
5. **合规是 2026 年的准入项，不是加分项**。GB 44495 / 44496 已强制、GB/T 32960 已升 2025 版、数据出境指引已出 2026 版，P0 进架构。

## 口径说明（重要）

- 文中容量、TCO、资源表的数字是**基于公开假设的推演**，不是任何生产系统的实测值，也不是报价。每个数字都标了假设与推导路径，便于被反驳。
- 待查证事项单列成清单，**不编、不猜**：给一个精确的错数字，比说清楚「这里还没有依据」更糟。
- 方案里的取舍都写了放弃了什么，包括「不做清单」——这份清单往往比功能列表更能说明边界。
